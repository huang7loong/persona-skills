# Persona Council（多视角独立推演圆桌）

通过让**彼此公理不同、甚至存在根本张力**的思维视角独立审视同一问题，帮助用户在“单一人物滤镜”之外看到完整的权衡维度。

## 核心原则：防止单上下文“和稀泥”

如果让同一个对话流里连续扮演 A 和 B，模型往往会提前妥协，导致观点趋同、缺乏真实锋芒。因此优先采用以下隔离策略：
- **多 Subagent 并行独立推演（优先）**：若当前 Harness 支持并行子代理 / subagent 机制（如 Antigravity 的 `invoke_subagent`、Claude Code / Codex 的 subagent 等），为每个参会人物启动一个独立 subagent，仅要求其加载自身对应的 `SKILL.md` 及 `references/` 独立作答，禁止相互偷看彼此结论后再修改立场。
- **单上下文严格分块（回退）**：若无法调用 subagent，必须严格分章节独立完成一方的全部公理推演与结论后，再彻底切换到另一方的底层假设重新审题，禁止在中途互相迎合折中。

## 两种圆桌模式

1. **多收录人物圆桌**：用户从 `skills/` 中指定 2–4 位已收录人物，各自独立回应同一议题。
2. **1+1 镜像对立模式（仅选定 1 位人物时自动启用）**：
   当仓库中仅选定 1 位人物（例如仅指定 `zhang-yiming`）时，自动为其匹配一个在核心公理上构成真实张力的“对立镜像视角”，避免单一思维体系形成回音室：
   - 若核心视角偏向**系统效率、长期理性、增长与可验证反馈**（如张一鸣）→ 自动配对**非功利人文直觉 / 体验与意义优先视角**，或**极端保守的反脆弱 / 尾部风险边界视角**；
   - 若核心视角偏向**内省修身、直觉体验或哲学思辨** → 自动配对**硬核工程实证与激励结构视角**。

## 四阶段推演流程

### 阶段 1：澄清问题与硬约束
先把用户的议题拆成可辩论的具体命题：
- 明确决策目标、时间尺度（1 年 vs 5–10 年）、不可突破的底线约束（现金流、家庭、健康、时间等）。
- 若用户输入过于抽象，先在提问或开篇要求补齐事实，或显式列出本次推演所做的最小前提假设。

### 阶段 2：各方独立推演
每位参会视角按统一结构独立输出（保持各自底层公理与推理算法）：
- **核心判断**：支持 / 反对 / 条件性重塑命题；
- **关键推理链**：基于本方公理得出的 3–4 步核心推演；
- **最担心的陷阱**：按本方逻辑，用户最容易在这件事上犯的错误；
- **建议的最小动作**。

### 阶段 3：主持交叉质询与分歧拆解
作为中立主持人，不要强行达成共识，而是把双方的冲突归类为三层：
1. **底层公理分歧**（不可调和的价值排序差异，例如“追求长期复利密度” vs “保护当下生活质感与确定性”）；
2. **事实假设分歧**（对行业趋势、自身能力、概率分布的判断不同——这类分歧可以通过实验/调研解决）；
3. **时间尺度分歧**（短期代价 vs 长期收益的权重不同）。

### 阶段 4：交给用户的决策综合台
输出一份简明收敛清单，**把最终决定权交还给用户**：
- 一个对比矩阵：不同选项在各方逻辑下的收益、隐含代价与最坏情景；
- 1–2 个能用来消解“事实假设分歧”的**低成本验证动作**（7–14 天内可落地）；
- 一个核心反思问题：*“在这个问题上，你更愿意承担哪一侧的遗憾？”*
